# Harbor 0.31.0 — security round

Fixes from a full security review of Harbor (decision 165). Update soon if your Harbor is published on the internet.

**What changes for you**

- **The console is never reachable from the internet.** With LAN mode and a public domain both on, anyone online
  could reach the Harbor login page by sending `Host: harbor.local` to your router's port 80/443. Harbor now only
  answers its LAN names to devices on your own network (and on this machine).
- **USB drives can no longer be a way onto the machine.** Drives are mounted with `nosuid,nodev`. A drive is never
  mounted on top of another one with the same label. A disk that holds the system is never offered for Format,
  whatever the hardware reports. Drives already mounted get the new options the next time they are mounted.
- **Recovery words are no longer stored in Harbor's database.** They are shown once, as before, and kept in memory
  for a day. Older words still in the database are removed when you update. If the daemon restarts before you have
  written them down, make a new Harbor recovery key in Settings → Account.
- **Login limits hold under parallel guessing**, and strangers can no longer lock you out of the machine itself (the
  CLI and a browser on the box always get their own tries).
- **Changing your password after a restart** now really moves your apps' unlock key to the new password.
- **The local certificate can only vouch for this machine and your home network.** New certificates are limited.
  If yours is older, Settings → Network shows *Replace certificate…*; afterwards trust the new one once per device.
- **An update that opens a new port asks first**, like an update that asks for a new permission. Update all and
  automatic updates skip it until you approve it.
- **Saved notification and backup passwords only go where they went before**: change the address and Harbor asks
  for the password again.
- Git-sourced apps: a build folder or Dockerfile that is a link out of the repository is refused.

**Not changed yet** (planned): one address per app (today apps on `harbor.local:<port>` share browser cookies),
signed releases, sealing app secrets.

Already running Harbor? Settings → Overview → Update, or `sudo /opt/harbor/bin/harbor self-update apply --to 0.31.0`.
