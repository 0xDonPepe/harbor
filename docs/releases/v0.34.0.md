# Harbor 0.34.0

Local AI groundwork: apps can use this machine's graphics card, and apps can have settings you change from their page.

- **Apps can use the graphics card.** An app that asks for it (a model server such as Ollama) gets the NVIDIA card when
  the NVIDIA container toolkit is installed (for computing), the render device of Intel or AMD graphics (not the
  display), or runs on the processor when there is none. The review asks you to allow it and says which card the
  app gets; the app's page shows *Graphics card … (in use)*, Settings → Overview, `harbor inspect` and `harbor gpu`
  show what Harbor found. An NVIDIA card without the toolkit is named with the commands to install it (Operator
  Guide, *GPU*); after installing it, restart Docker (Harbor waits for that, rather than start an app that would
  fail), then Restart the app. Adopting such an app from a drive asks you to allow it too.
- **App settings.** An app can offer settings such as a model server's context length or keep-alive time. The
  install review has a collapsed *Options* section with the defaults filled in; the app's page lists the current
  values and *Change…* opens a form, then the usual review ("Context length (tokens): 8192 → 16384"). Only the values
  you change are kept: the rest follows the app's package (a value you chose stays yours even when a later version
  makes it the default). Your values stay through remove and reinstall, go with
  backups and restores, and are deleted with *Uninstall completely*. CLI: `harbor settings <app>`, and
  `--set id=value` on `install`, `update`, `configure` and `apply`.

For app authors: two additions to the package format, first accepted by **0.34.0** (declare
`release.minHarbor: "0.34.0"` in an app that uses them):

- `permissions: {<service>: [gpu]}` — a fourth permission next to `net-admin`, `tun` and `ip-forwarding` (decision 179).
  On a service granted it, `NVIDIA_VISIBLE_DEVICES`, `NVIDIA_DRIVER_CAPABILITIES` and the other NVIDIA selection
  variables are Harbor's (not a compose literal or a binding target).
- `settings:` — typed values (`integer`, `number`, `boolean`, `string`, `choice`) with a default and limits, bound to
  environment variables (decision 180). See *Settings the operator can change* in docs/DEVELOPER_PACKAGES.md.

Packages for earlier Harbors work unchanged.

Also fixed: adopting an encrypted app from a drive on another Harbor machine failed with an internal error (it
recorded the app's folder before the app itself); it now works, and adopting an app that asks for permissions
asks for them first. Not verified on a real graphics card yet: the first live test is an
RTX 3090 machine.

Already running Harbor? Settings → Overview → Update, or `sudo /opt/harbor/bin/harbor self-update apply --to 0.34.0`.
