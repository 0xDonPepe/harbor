## Harbor 0.28.2 — apps say which Harbor they need

Everything in the [0.28.1 release](https://github.com/carlosalaniz/harbor/releases/tag/v0.28.1)
still applies. New in this release:

- **Each app says which Harbor it needs.** An app package can state the oldest Harbor it runs on
  (`release.minHarbor` in its manifest). The app catalog's checks prove it against that real Harbor
  release before publishing. If your Harbor is older, the App Store shows "needs Harbor x.y.z or newer"
  instead of an error. Updating Harbor makes the app available.
- **Your own apps too.** Uploading a package (or adding a git source) that needs a newer Harbor is
  refused with the same message, before anything else is checked.
- **Release safety.** A Harbor release is never re-published under a version that was already released
  from other code.

For app authors: leave `release.minHarbor` out when the app works on Harbor 0.28.0. When you set it, it
must be 0.28.2 or newer, written plainly (`0.28.2`, not `0.028.2`): 0.28.0 and 0.28.1 do not know the
field. See docs/DEVELOPER_PACKAGES.md §10.

What not to trust yet:

- Tested on the developer machine only (automated suites). No published app declares
  `release.minHarbor` yet, and the app catalog's checks against real releases have not run on GitHub
  yet. See [VERIFICATION.md](../VERIFICATION.md) §3s.
